ONE REMAINING LIVE-MODE COMPATIBILITY ISSUE — P2
Source: apps/api/recovery_api/agent.py:run_model_loop / _usage_add;
apps/api/recovery_api/investigate.py:_live_agent;
evaluations/runners.py:tool_agent / run_live_evaluation;
docs/INTEGRATIONS.md:local model instructions.

The agent always has a dollar-cost ceiling, but the provider adapter records a
price only if the response supplies cost_usd. A provider without that price yields
cost_known=false. App live mode has no configured allow_unknown_cost policy, and
live evaluation explicitly disables it. Both therefore stop after the first
provider call with cost_unknown, before even executing the requested read tool.
This is intentional conservative behavior, not a silent unsafe write, but it makes
the documented local-model setup unusable for a complete investigation when the
server omits price. It also affects hosted responses that omit price.

Independent controlled probe (no network/model calls): response requested
get_source_customer, reported30tokens and cost_usd=None. Observed provider_calls1,
error budget_exhausted, reason cost_unknown, tools_executed0.

Required before a live-model demo:
- Define and document a provider-specific cost policy consistently in app and eval.
- For a configured local server, explicitly opt into unknown monetary cost while
  retaining hard tool/time and response-token constraints; label compute cost
  unmeasured, not automatically zero.
- For hosted models, prefer explicit configured input/output rates and a recorded
  conservative estimate, separately labeled from provider-supplied charges.
- Never silently call missing cost zero. Unsupported accounting should explain
  what to configure, and should continue to stop under the strict policy.
- Test missing-price live app and evaluation behavior with fake provider responses;
  test strict unknown-cost rejection, estimated-cost accounting and override scope.
- No paid calls or credential/account changes without Vinay's authorization.
